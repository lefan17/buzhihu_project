## 项目体检：不止乎（buzhihu）内容社区

对 `buzhihu_project/buzhihu_project`（Spring Boot 2.5.9 + Vue 2.6）做了全面审查，产出 `项目体检报告.md`（项目根目录）。

技术画像：后端 82 源文件 / 前端 50 源文件 / 13 张表 / 16 个模块 / 零测试 / 无 git。

查实的三个致命缺陷：
1. **匿名浏览失效**（产品不成立）—— `WebConfig` 拦截 `/**`，仅放行 login/register/files/static；前台首页 6 个只读接口全被拦截返回 401，`request.js` 见 401 跳登录。与 `router/index.js:145` 注释「前台允许匿名浏览」的设计意图冲突。
2. **IDOR 越权** —— `BlogController.deleteById/updateById` 零归属校验，且 `JwtInterceptor.requireAdmin()` 的 URI 前缀矩阵里完全没有 `/blog/` 规则，任意登录用户可删改他人博客。`startsWith("/category/select")` 这类前缀匹配还把 `/category/selectPage`、`/notice/selectPage`、`/activity/selectPage` 误放行给普通用户。
3. **存储型 XSS 两处入口** —— `v-html` 渲染 blog/activity content 且后端无 jsoup 过滤；`FileController.upload` 不校验类型、直接用原始文件名拼路径写入，且 `/files/**` 在拦截器排除名单。

其他：密码 MD5 无盐、JWT 密钥=用户密码、CORS 全开、SQL 与 .env 硬编码 localhost（部署即坏）、无 git/.gitignore/README/测试、files/ 70MB 含大量重复。

产品设计评价：数据模型完整度高（notification/report/follow/activity_sign 四表体现社区定位，超出个人博客范畴），用户侧闭环完整（我的博客/收藏/点赞/评论/报名+公告栏+举报闭环）。半截工程：标签存 JSON 但不可点击无聚合页；无找回密码、无草稿箱、无回收站、无敏感词过滤、搜索仅按标题。

## 排查方法上的教训（重要）

在 Windows/Git Bash 下用 Grep 做"功能是否落地"的判断时必须注意：
- 路径大小写会漏匹配 —— `Front.vue` 与 `front/` 目录并存，用 `views/front` 搜会漏掉 `views/Front.vue`，我因此一度误判"公告前台无入口"（实际有顶部滚动公告栏）。
- 组件化调用会漏匹配 —— 搜 `collect` 在 `Person.vue` 无结果是因为它用 `<blog-list type="collect">` 组件而非直接调接口，一度误判"收藏无入口"（实际有"我的收藏"tab）。
- 结论：判断"某功能是否有前端入口"时，应先 grep 页面级关键词（tab 名、label）再 grep 接口名，且路径用项目根而非子目录。

## 第二轮：根因定位与改造建议

用户（阿帆）补充：项目来自 GitHub 同名仓库。`gh` 未登录（`gh auth status` 提示未登录），WebSearch 也未搜到公开 buzhihu 仓库，上游未确认。但代码内的脚手架痕迹足以定性。

**核心洞察**：三个致命缺陷不是编码失误，而是「后台管理脚手架基因 vs 内容社区需求」冲突的产物，四个维度全部对立：

| 维度 | 脚手架假设 | 社区需求 |
|---|---|---|
| 访问模型 | 全员登录 | 游客可读 |
| 权限粒度 | 模块级 | 数据归属（我的只能我改） |
| 内容生产 | 管理员录入 | UGC |
| 输入可信度 | 内部可信 | 公开不可信，须清洗 |

脚手架痕迹证据：库名 `xm-blog`、localStorage `xm-user`、邮箱 `admin@xm.com`、title「管理系统」、根目录 `springboot2+vue2脚手架源码+sql.zip`。

**这个洞察比逐条 bug 更有解释力** —— 之后给建议时应从「重新校准产品定位」切入，而非罗列修复点。

已追加「二次开发改造建议」章节到 `项目体检报告.md`：定位二选一（公开社区 / 私域社区，关键在前后端对齐）→ 去脚手架化 → 差异化功能（标签独立表、全文搜索、找回密码、草稿箱、敏感词、消息中心，按性价比排序）→ 工程门面（git/README/Swagger/docker-compose）→ 毕设视角（复盘文档比堆 CRUD 有说服力）。
